# 每轮回复用量显示方案

已选行为：在每条最终 AI 回复的操作栏旁显示本轮问答用量，点击查看明细。

## 数据来源与方案比较

推荐读取本机 Codex 已有会话记录中的 token_count、轮次标识和开始/结束事件，按轮次汇总；本机已确认存在这些记录。这样能回看已有数据，不触发模型推理。另一方案是只监听实时用量通知，但单独启动的后台不一定收到桌面客户端的轮次事件，历史记录还需补读，因此不作为主要来源。需要核实页面回复节点与记录中轮次标识的对应关系，无法可靠匹配时不按列表下标猜测。

## 显示与口径

- 在截图所示回复操作栏旁显示“本轮 xx Token”；生成中显示“统计中”，完成后更新。
- 点击明细展示本轮输入、缓存输入、输出、推理输出和总 Token。缓存输入属于输入的子项；推理输出与输出的包含关系按记录语义处理，不重复累计。
- 一轮包含该用户请求引起的多次模型请求和工具往返；不只统计最终可见文字，也不把整段聊天累计量当成本轮用量。
- 订阅额度只能提供账户窗口快照，无法从 Token 精确换算本轮扣除的额度。若同一窗口中存在轮次前后快照，显示“期间账户额度变化（参考）”；明确它可能包含并行聊天的消耗，并受刷新延迟及百分比精度影响。
- 窗口重置、快照缺失或无法匹配时显示“暂无数据”，不显示假零值或伪造精确费用。
- 本地数据缺失的云端/远程会话显示不可用；优先确保本地聊天准确。

## 资源、更新与边界

新增统计只读取本机已有记录、计算和渲染，不为统计调用模型，不发送聊天正文或日志到 GitHub。使用缓存和增量读取控制磁盘与 CPU 开销。原账户额度圆环继续使用现有的只读查询。

保留现有启动入口；新增逻辑放在本包自有文件中，避免改写上游 vendor 文件。需保证上游自动更新不会悄悄移除新增模块；如集成方式需要改变更新策略，实施前明确说明。

## 验证与交付

使用合成记录验证多次请求聚合、缓存/推理口径、重复事件、重置和缺失数据；验证多个轮次和页面切换时不串数据；在当前客户端检查操作栏布局。更新 README、安装包与校验文件，然后更新已授权的 GitHub 仓库。验证未完成的范围应在交付说明中明确。
